# Experimental window-conditioned DynSphere-E

This isolated research prototype tests a history-conditioned normal-dynamics
hypothesis. Methodological novelty and accuracy gains remain unestablished.
The existing detectors, historical results, manuscript, and official VUS
evaluation code are unchanged.

## Model

A causal convolution and GRU encode the 100 observations preceding each
target. Training uses normal-data forecasting and optional window
reconstruction. A frozen encoder supplies Euclidean states and adjacent-window
velocities. One or four normal regimes define ridge predictors of the next
observation increment. A Gaussian mixture with normal-calibrated, fixed
diagonal covariances supplies the anomaly score.

Reconstruction contributes to representation training. The anomaly score
uses the predictive observation density. The local dynamics are fitted after
the neural representation is frozen. The neural forecast head remains a
separate control. These changes affect representation, prediction, and scoring,
so this model is a separate experimental family member in comparisons with E1/E4.

## Data and numerical contracts

- The normal training split is chronological 80/20 within each entity.
- Internal standardization uses the first 80% only. Dataset loaders can have
  applied an additional full-normal-training transformation; that historical
  preprocessing remains disclosed.
- Every window ends before its target and stays within its entity. No
  training history is prepended to the test suffix.
- The first 100 test rows per entity have NaN scores and a false validity mask.
- The initial implementation supports regular sampling only. Dataset loaders
  that provide observations without timestamps cannot establish the regularity
  of the underlying source timestamps; their row-order preparation is explicit.
- Latent velocity always uses adjacent histories, including when fitting
  targets are subsampled.
- Requested and effective regime counts are recorded, including cluster merges.
- Neural training uses float32, fixed seeds, one Torch thread, 10 epochs, and
  at most 20,000 selected targets. Residual densities use float64 arithmetic.
- Batch-size comparisons permit 1e-4 absolute and 1e-6 relative score differences
  because float32 recurrent computation can depend on batch shape.

## Bounded pilot

The frozen selection includes three Exathlon cases, three GHL cases, one
GutenTAG case per each of its six mechanisms, and the three principal
industrial datasets. Seeds and mechanisms follow the approved design.
No configuration or source is selected according to observed test accuracy.

Eight configurations produce 120 planned result records:

1. One regime, forecasting-only representation training.
2. One regime, forecasting plus reconstruction training (primary).
3. Four regimes, forecasting-only representation training.
4. Four regimes, forecasting plus reconstruction training.
5. Channel-independent one-regime control.
6. Window-ridge control.
7. Compact neural forecast-head control.
8. Previous single-regime neural predictor, with its existing 80/20 split.

Identical neural representations are cached across regime counts and reused
by the compact forecast-head control. Each logical execution still receives
its own record, scores, metrics, and timing metadata. Reused representation
timings measure reuse/refitting cost, and must not be presented as fresh
end-to-end neural training times. Each execution runs in a fresh process.

PowerSystem remains a declared case but is marked incompatible because its
historical loader uses the same raw source for training and testing. It needs
a separately approved disjoint protocol. Missing data, incompatible inputs,
worker errors, and timeouts remain explicit records. The controller uses a
two-hour limit per execution. No replacement cases are selected.

Outputs are separate under `results/window_dynsphere_v1/`. A manifest includes
source/package identities and frozen raw-input hashes. Each successful record
also hashes its input arrays, scores, and labels. Resume checks refuse changed
sources or corrupted successful artifacts. A missing input that appears later
requires a new manifest. Failed attempts are archived separately, and current
summaries exclude historical successes whose latest attempt failed. The
controller exits unsuccessfully when any worker exits unsuccessfully.
Representation caches are trusted
local artifacts generated by this runner; do not import pickle files from
untrusted sources.

## Execution

From the code repository, using its existing virtual environment:

```bash
.venv/bin/python -m research.window_dynsphere.pilot --dry-run
.venv/bin/python -m research.window_dynsphere.pilot --run
.venv/bin/python -m research.window_dynsphere.pilot --resume
```

Use `--manifest /absolute/path/to/frozen-manifest.json` to resume the exact
campaign explicitly. Source changes require a new manifest. The original
manifest and results are preserved. This runner contains no HPC submission.

To aggregate an existing frozen campaign:

```bash
.venv/bin/python -m research.window_dynsphere.pilot \
  --manifest /absolute/path/to/frozen-manifest.json --aggregate
```

`per_family_available.csv` includes case counts for available results.
`per_family_matched.csv` includes only cases completed by all eight
configurations. Read `completion.json` and `noncomplete.json` with both tables.
Historical reference scores are separately re-evaluated on the common
100-row exclusion when available and label-aligned. Their differing fitting
budgets remain explicit; missing references are listed in `reference_issues.json`.

The pilot is exploratory. These source families already informed model
development. Additional detector seeds on the same cases do not supply an
independent confirmation dataset. A larger campaign requires an explicit
decision after reviewing all pilot outcomes.
